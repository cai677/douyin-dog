# 直接文案：逐句配音与三档倍速试听

本场景输入为用户一次性提供的完整文案及所选音色，不要求飞书文档、参考视频或原时间轴。以下是已确定的执行规范；旧版voice_draft.py未实现此入口，不能直接运行它并声称已支持。执行时需按本规范组织TTS、裁剪和保音高变速，并保存真实产物与检查记录。

## 1. 整理文案并确认

- 保存原文，按标点断为逐句行，连续编号line001等，保留原顺序、文字及重复句，去掉断行输出中的标点符号；原文单独保留，不套用飞书表格的连续重复去重规则。无删改授权不改写文案。
- 逗号、句号、问号、叹号、分号、冒号、顿号及对应英文标点均作断句边界；换行也作边界。连续标点（如？！、……）作为一个边界，不生成空行。引号、括号等标点不出现在断行文案中，其内部文字保留，不生成仅含标点的行。数字小数点、网址等内部符号不机械切断或直接删除，以免改变原意；需要无标点朗读表达时，在确认清单中明确对应读法。断行清单、TTS文本及对应字幕采用确认后的无标点文案。
- 简短说明音色名称、完整ID和配音要求；本轮试听仅用前三个非空断句（不足三句则全部）制作1.2x、1.3x、1.4x试听，以及采用的气口标准和默认语气。按SKILL.md“新任务直接执行”处理：设置明确时直接制作指定试听，不再重复要求确认。
- 没有明确总时长要求时，按真实音频时长输出，不索要飞书时间轴，也不拉伸音频凑总时长。

用户直接指定一个正式倍速且没有要求试听时，跳过第2节，直接逐句生成全篇、处理气口并交付剪映草稿；不要强制增加试听或确认。豆包凭据使用SKILL.md中的本机读取方式。

## 2. 先处理首尾，再做三档试听

- 试听阶段只为确认后的前三个非空断句生成原始TTS音频，保留原件；剩余句子此时不得生成。相同文案、音色、服务参数可复用缓存。每句先独立处理句首和句尾多余气口，保留自然发音，不只裁整段首尾。
- 已校准音色采用确认的专属设置；新音色按紧凑规则作为候选，不能标为已批准。保留每句裁剪区间和参数，检查轻声首字、尾字及句间衔接；不能把低电平直接当静音。
- 从同一份裁后音频分别生成1.2x、1.3x、1.4x三个实际可播放的试听版本。使用保音高的时间伸缩；不能仅改文件名/播放器标签，也不能改变采样率让音调升高。TTS语速参数不直接等同于这些播放倍速。
- 仅前三句提供三档逐句试听音频，通常共9个文件（不足三句按实际句数乘3），名称包含句子编号和倍速；按倍速分组便于选择。可额外提供同内容连续试听供比较节奏，但不能替代逐句音频。
- 三档使用相同文案、音色、原始音频和裁剪区间，只改变倍速。变速后复查首尾留白和声音边界，不加额外长空白，不用降速补回被裁掉的时长。
- 展示可播放试听，并等待用户选择一个统一倍速；尚未选择时不得替用户决定或标记正式朗读已完成。

## 3. 选定倍速后完成朗读与剪映草稿

- 用户选定后，才生成剩余句子并逐句处理首尾气口，全篇每句使用同一个选定倍速及确认的气口标准。剩余句子只制作选定倍速，不再生成三档。已生成且输入一致的对应试听文件可直接复用为交付音频，不重复调用TTS。
- 若用户要求修改气口、文案或音色，更新受影响的试听供确认，不将旧试听批准自动套到新设置。
- 交付每句独立WAV、逐句文案及文件顺序清单，记录音色名称/ID、倍速、真实时长和裁剪信息。可提供连续试听，独立文件仍保留。
- 此场景默认最终交付剪映草稿，试听和配音都是中间步骤。用户选定倍速后继续生成全篇并将逐句独立音频和无标点字幕按真实时长连续排列，生成并安装新草稿，不再要求用户另行提出制作草稿。仅用户明确只要音频时例外。默认系统字体、字号9，用户指定优先。已烘焙选定倍速的音频在草稿里设1.0x，避免重复加速；保留原速裁后音频并在草稿设选定倍速也是可选实现，但只能加速一次。

## 4. 检查与状态

- 试听数量为min(3,总句数)×3；正式交付逐句数量与完整分句清单一致，无漏句、空句或擅自去重；断行文案不带标点。三档均可解码，音色和内容来源一致，实际时长应近似裁后原速时长除以倍速；记录变速工具及取整误差。
- 检查每句首字、尾字及连续衔接；机器检测不等于用户试听通过。记录所选倍速、气口反馈和确认范围。
- 区分“规范已写入”“试听已生成”“用户已选定”“正式朗读已完成”；未运行的检查标未运行。新文案的倍速选择不自动成为所有未来文案的固定倍速。

- 草稿交付检查：音频字幕逐句对应、ID唯一且内容/元数据/索引一致、媒体路径有效、源区间合法、无重复加速。安装到实际剪映目录，保留旧稿；实际打开并检查可编辑性，无法进行时如实标记待验证。音频生成成功不等于剪映草稿任务完成。
