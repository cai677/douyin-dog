## 2. 稳定目录与资料职责

以下路径以项目根目录为基准。

```text
assets/inbox/                         原始投料，只读
assets/catalog/assets.jsonl          原视频索引，一条记录对应一份内容
assets/catalog/clips.jsonl           片段索引，一条记录对应一个源区间
assets/catalog/taxonomy.json         现有分类和标签字典
assets/catalog/analysis/<asset_id>/segments.json
                                     候选切分及解码检查记录
assets/catalog/frames/<asset_id>/     片段首、中、末参考帧
assets/catalog/previews/<asset_id>/   静音低清预览
assets/classified/<product_id>/      固定分类浏览入口
assets/templates/<template_id>/      审定模板及素材池，按需建立
work/<任务>/                         本次脚本、标签复核、报告和日志
```

原片、派生预览和生产素材用途不同：文件夹内预览用于浏览，正式剪辑按索引返回原片高清区间。预览不是最终交付视频。本批预览保持源比例、源帧率、1.00x，宽不超过 320、高不超过 568 像素，不带声音。

分类目录通过硬链接引用派生预览，不额外复制整套媒体。硬链接共享文件内容，不应在浏览目录直接修改视频；修改分类应回写标签并重建对应浏览项。原始视频不建立可被浏览操作改写的派生替身。

## 3. 六个固定主分类

每段只分配一个主要类别；产品、对象、颜色、动作等用标签表达。一个片段可以被多个参考模板引用，不为每个模板再复制一套素材库。

| 主分类 | 判断依据 | 当前宠物电推示例 |
| --- | --- | --- |
| 01-产品展示 | 主要在呈现产品本身 | 外观、包装、刀头、配件 |
| 02-使用动作 | 主要在实际操作或使用 | 修脚毛、耳部修剪、梳理 |
| 03-使用场景 | 主要交代环境、对象活动或使用背景 | 室内活动、猫砂盆、人物讲解 |
| 04-对象细节 | 主要呈现被处理对象局部 | 脚底毛、宠物局部细节 |
| 05-功能演示 | 主要展示某项功能的操作过程 | 充电、照明、水洗画面 |
| 06-效果展示 | 主要展示处理结果或可见对照 | 修剪结果、前后对照 |
| 99-待确认 | 无法直接归入可检索生产候选或需要隔离 | 黑场、极短片段、参考副本、其他型号、混合动作 |

先看画面主要用途，再定分类。仅看到脚部不等于“效果”，仅看到水洗不等于已经证明防水性能。前后对照应核实对象及条件，不能将不相关片段拼成事实证据。

动作、物种、颜色等具体编码以 taxonomy.json 为准。当前例子：`trim`=脚毛修剪；物种 `c/d/n/u`=猫/狗/无宠物主体/待确认；颜色 `l/y/m/o/u`=浅色/黄绿色/多色或多产品/其他型号/未见产品或待确认。颜色不是型号证明。

换商品时保留主分类，新增适合该商品的动作等标签；不把“猫狗”“修脚毛”强加给其他商品。修改标签字典应同步发布程序和查询规则，不能只改文件夹名。

## 4. 入库和分类步骤

1. **清点投料。** 区分视频、图片、音频；确认复制完成和文件稳定，记录数量、路径、大小。图片和音频不套用视频切分流程。参考单独指定并登记来源身份。
2. **登记内容身份。** 计算完整 SHA-256，建立稳定 asset_id 和来源别名。相同内容改名不作为新原片；S01 等只用于浏览，跨任务身份依赖 asset_id，不依赖排列顺序。
3. **读取缓存。** 内容和分析版本一致时复用已有分析；同时检查所需预览、参考帧和区间数据完整。缓存存在不代表本次重新执行了解码验证；明确记录复用或重跑。
4. **完整解码与候选切分。** 读取源帧率、尺寸和帧数，检测候选镜头边界。保持来源区间连续可追溯；快动作造成的误切、漏切需通过画面复核修正。
5. **导出预览和参考帧。** 每段记录起止帧、秒数、时长，导出首中末帧。检查预览可解码、帧数符合区间、路径存在，核对处理前后原片哈希。
6. **逐段画面分类。** 查看参考帧并记录分类依据。当前实现由助手查看画面后写入标签，不是脚本自动理解内容。依据不足时查看更多时间点或播放预览，不能根据标题猜标签。
7. **检查长段及混合动作。** 本批对至少 8 秒区间补看多点采样。含多个用途时进一步圈选有效区间，暂未圈选的进入待确认；长镜头不是必须按固定秒数切碎。
8. **处理限制与重复。** 记录字幕、水印、遮挡、黑边、其他型号、身份不明和参考副本；对视觉相似只记录候选关系，必要时核实源区间。
9. **发布索引和分类入口。** 标签数必须与片段数一致。每段一个主目录，多维信息保存在索引。保护已有审核结果；先检查新索引再替换，保留可恢复记录。
10. **提交批次报告。** 报告原片数、区间数、类别分布、待确认/隔离数、重复依据、检查结果、未执行项和下一步；同步任务说明。

自动检测只提出切点，初步分类不等于动作完整、型号一致或成片可用。选入具体镜头前必须复核可用源区间。

## 5. 索引字段和状态

| 信息 | 当前片段索引字段 | 使用要求 |
| --- | --- | --- |
| 身份 | `asset_id`、`clip_id`、`display_id` | clip_id 与源帧区间关联，不能用显示名代替身份 |
| 来源 | `source_path`、`source_start_frame`、`source_end_frame_exclusive`、`fps` | 路径相对项目根；区间左闭右开 |
| 时间 | `start_seconds`、`end_seconds`、`duration_seconds` | 选用区间不得越过原片真实范围 |
| 产品及画面 | `product_family`、`sku`、`species`、`action`、`product_color` | 当前 product_family 是商品库分组，未核实的 SKU 保持 unverified |
| 浏览与证据 | `main_category`、`browse_category`、`preview`、`browse_preview`、`frames`、`classification_basis` | 最终判断看画面，不只看文件名 |
| 限制 | `review_flags`、`boundary_status`、`character_identity` | 不把空缺信息当作已确认 |
| 入库状态 | `library_status` | classified_candidate 为可筛选候选；hold 为待确认/隔离 |
| 审核 | `production_approval` | 当前均未批准；下游以具体模板与区间批准记录为准 |
| 查重 | `preview_sha256`、`duplicate_group_id`、`similarity_candidates` | 当前 exact 组指预览字节相同，视觉候选不等于确认同源 |

推荐阶段关系：待分析 → 待画面复核 → 已分类候选或待确认 → 模板候选 → 模板区间批准 → 生产。阶段概念不应擅自写成未经实现的新枚举。模板审核通过不能倒推全片、所有用途都通过。

切点变更会产生新的 clip_id；保留旧新映射及审核历史，受影响的模板候选标需复核。不能把旧区间的批准直接套到扩大后的区间。

## 6. 围绕参考视频快速筛选

先将参考每镜头写成需求：商品/型号、对象、动作、场景、景别、最低时长、角色连续性和构图等。主分类只缩小浏览范围，不能代替这些条件。

筛选顺序：商品及型号 → 排除 hold/参考副本及硬性不符 → 对象/动作/时长等约束 → 参考画面对照 → 来源与视觉重复关系 → 可用区间审核。

例如“猫、浅色电推、脚毛修剪、至少 2 秒”：本批索引实际得到 17 个候选，再优先选不同来源、避开已知相似邻居，返回 5 个供看图审核。17 个候选不代表 17 个独立原创镜头，也不代表与指定型号已匹配。

审核通过后，将模板镜头、clip_id、批准起止区间、理由、限制和审核结果写入 matches.json；成熟模板复用 pools.json。当前分类发布不会自动批准或修改上述文件。

同商品换参考：复用片段索引，新建 template_id，重做参考需求和镜头匹配。

换其他商品：使用独立商品分组，沿用六类，新增该商品标签；可以借鉴参考的语义顺序，但实际产品画面必须属于目标商品。无法确认型号时保留待审。当前程序尚未支持通用多商品自动发布，执行前需适配并验证合并索引。

## 7. 重复识别和增量规则

- 完整文件 SHA 相同：登记别名，复用分析。SHA 不同：只能说明字节不同，仍可能画面相同。
- 预览 SHA 相同：当前登记 exact 组；编码或区间变化可能使该值变化，不是跨编码通用身份。
- 三帧视觉指纹相似：记录待复核关系，不删除原片、不直接判为已确认重复。
- 批量成片还需按 AGENTS.md 检查组合、共用画面和历史输出；素材分类阶段不能替代成片查重。
- 新增文件只分析新增内容；改名更新路径别名；旧素材临时缺失先标缺失，不应从总库及历史静默删除。
- 同时只允许一个发布过程更新总索引。重跑保留审核、型号确认及历史；预览或分类变化时复核受影响批准。
- 升级切分算法先在代表素材验证，记录版本及旧新区间映射，不为“刷新”而整库重切。

## 8. 当前脚本的真实使用范围

以下程序均在 `work/2026-09-08/`，保留本批运行位置，不直接迁移以免破坏路径推导。

| 程序 | 实际职责 | 执行前提 |
| --- | --- | --- |
| `batch_ingest.py` | 扫描 MP4、哈希、缓存、切分、抽帧、预览与验证 | 绑定当前任务参考及 inbox；确认投料稳定 |
| `batch_review_long.py` | 校验标签数量、生成长段抽帧检查图 | 已有 segments 和逐片标签；生成图不等于看过图 |
| `batch_publish.py` | 使用已写标签发布片段索引、目录、相似候选和报告 | 人工/助手画面复核已完成；标签与区间一致 |
| `query_library.py` | 从已发布索引按条件查询候选 | 可只读检索，不触发切分或批准 |

本批实用 Python 为 `C:/Users/Admin/AppData/Local/Programs/Python/Python312/python.exe`，具备 OpenCV、NumPy 和 Pillow；换环境先检查依赖。

只读查询示例（在项目根目录使用 PowerShell）：

```powershell
& 'C:/Users/Admin/AppData/Local/Programs/Python/Python312/python.exe' 'work/2026-09-08/query_library.py' --product pet-trimmer --species c --action trim --color l --min-seconds 2 --limit 5
```

查询器目前只支持商品分组、物种、动作、颜色、最短时长和数量等条件；没有实现自动参考图匹配、精确型号确认、全部构图条件或成片生成。默认不返回 hold，可显式查看待确认用于复核。

当前发布程序固定 `pet-trimmer`，使用本批标签与清单写出总索引。不能直接用它发布第二种商品或不完整清单，否则可能遗漏其他记录。新商品或跨批次发布之前，必须实现按稳定 ID 合并、缺失记录保留及审核保护，备份并核对覆盖范围。当前缓存判断也不包含所有派生帧的完整性验证，应补查缺失文件。

当前代码含审核字段保留逻辑，但跨商品合并、并发锁、切点迁移、健壮的裁切同源识别仍是待完善能力，不能从长期规范推断程序已经支持。

本批切分版本为 `frame_diff23_gap035_v2`，帧差阈值 23、最小候选间隔约 0.35 秒；小于 0.4 秒片段进入待确认。这是本批参数，不是所有商品的永久标准。三帧指纹使用 `dct32_low8_median_ac_v1`；相似候选阈值为单帧最大汉明距离 12、三帧总和不超过 24、平均 BGR 差不超过 20，仅为待复核筛查。
