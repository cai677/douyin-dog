# 项目长期执行规范：爆款模板与批量带货视频

## 1. 目标与原则

以用户选定的爆款参考视频建立镜头模板，将统一投入的生产视频自动切分、分类并建立对应镜头素材池，再按时长、连续性和差异化约束批量生成带货视频及可编辑剪映草稿。

生产单位：一个产品 + 一个参考模板 + 多个镜头素材池 + 多个成片版本。复用已审模板时只增量处理新增素材和新组合。

“去重”指素材重复识别、版本差异控制和历史重复检查，不保证平台判定原创或流量。改文件名、镜像、调色、加边框、换编码不算有效内容差异。

用户当前指令优先。单次产品、数量、时长、音色和例外放任务目录，不变成全项目默认。本文件是长期规范，不代表程序已实现；完成状态必须有真实运行产物和验证依据。

## 2. 统一投料与目录

用户将待整理的生产视频统一放入 assets/inbox/，不要求预先分类。参考视频单独放在任务目录并明确指定。批量放入多个产品时，先识别产品并分组；无法确认产品型号或画面含义时标记待审，不混入已批准素材池。

根目录只保留稳定结构，目录按需创建，旧任务不强行迁移。

```text

    frames/<asset_id>/               # 首中尾帧、必要的动作帧
```

- assets/ 中的原始素材只读或复制，不移动、覆盖、破坏。现有其他位置的素材也可登记，不必全部搬入 inbox。
- 切分默认生成带来源区间的片段索引及预览；生产时按批准区间导出或复制。原片不能被直接切碎替换。
- 分类采用索引与标签，一个片段可多标签、多模板引用，避免为每个分类重复复制整库。
- 参考与生产素材分开标记；参考不能自动进入生产池，除非用户明确允许将其作为生产素材。
- 完整参考负责原始音频、顺序和总时长；video_clips/ 负责视觉匹配；material/fragmentNN/ 中经 matches.json 批准的素材才可生产。文件存在不代表通过。
- 采用新配音后，以真实语音和明确加入的停顿决定画面及字幕时间，参考时长作为整体目标。
- 所有路径明确基准：任务相对路径或素材库相对路径，不能混用。归档须修复草稿路径。
- 通用程序成熟后可增加 tools/，单次脚本、备份和日志仍放任务目录。

## 3. 每次执行先读取

### 已确认的跨商品分类规则

每个商品库共用六个固定主分类：`01-产品展示`、`02-使用动作`、`03-使用场景`、`04-对象细节`、`05-功能演示`、`06-效果展示`，另有 `99-待确认`。浏览目录为 `assets/classified/<product_id>/`，每段只进入一个主分类，猫狗、颜色、照明、具体动作等保存在标签中，不继续扩建分类树。

匹配顺序是商品/型号 → 参考镜头需求 → 动作/对象/场景/时长约束 → 画面排序。不同商品独立检索；同商品换参考只重建模板匹配，不重复分析原素材。固定分类只是浏览入口，不能代替视觉匹配或型号审核。

批量分类允许用抽帧辅助完成主分类，但必须记录观察依据、候选切点状态、长段/混合动作和型号未确认等限制；分类完成不等于已批准进入成片。重编码相似度只能记录为候选关系，不能未经复核声称全部属于重复内容。

`assets/catalog/` 保存稳定索引；分类浏览区可通过派生预览的硬链接避免重复占用空间。原片不改动。后续调用优先从总索引筛选，不重新遍历全部原视频。

先读本文件；素材入库、分类和筛选还应读 [素材库切分分类执行规范](material-classification.md)，再读当前任务说明、最新报告和所需索引；进入模板匹配或生产时读取 recipe.json、matches.json。从最后通过的阶段继续，不重复索要已确认信息。

文档协同：本文件负责全项目通用要求，执行细则负责素材阶段的方法与当前实现边界，任务说明负责单次授权与进度，机器索引负责实际素材记录，批次报告负责验证证据。执行后同步任务说明与报告；长期规则变化才更新主规范和细则。旧计划及试处理记录按日期保留，不能作为覆盖最新状态的依据。当前单批脚本尚未通用化，跨商品发布前必须检查索引合并和审核保护，不能直接按完整流程规范推断程序已实现。

任务记录：task_id、产品/型号、参考来源、template_id/版本、数量、平台、目标时长/容差、文案修改权限、音色、字幕样式、素材来源和特殊限制。缺项先完成不受影响的工作，再集中提出必要问题。

默认保持参考语义顺序，以生产素材替换画面。数量是目标，不是硬凑要求；有效组合不足则报告实际数量与缺料。

## 4. 工作流

### A. 接收参考与检查能力

1. 创建任务目录，复制完整参考并校验哈希，不修改源文件。
2. 检查解码、时长、帧率、分辨率和音轨，记录实际工具结果。
3. 检查 ASR、豆包 TTS、音频处理、视频渲染和剪映草稿能力。密钥不写入文档、JSON 或日志，只记录配置名与可用状态。
4. 缺配音配置不阻塞拆解、入库和匹配，但不能把静音片算作完成的配音成片。

阶段出口：参考身份、媒体信息、任务约束和能力缺项可追溯。

### B. 拆解爆款、审定模板

1. 自动检测候选切点，抽取首中尾帧和切点前后帧，结合视频复核误切、漏切、过短片段。快速动作不能只凭帧差判成切换。
2. 从完整参考音轨运行可用 ASR，或整理用户提供文案，核对产品名、数字和句意；记录真实文本来源，不将手工整理说成 ASR。
3. 标记实际语义功能：开场、问题/场景、产品、演示/证据、效果/收尾等，不强行套全结构。
4. 每镜头定义：画面需求、产品可见度、动作、景别、角度、场景、光线、构图、角色连续组、参考时间、适用文案段、时长范围和可变顺序。
5. 语义段与镜头分开编号，一个配音段可包含多个镜头，不能机械“一刀一句”。
6. 审定模板带版本；镜头 ID 稳定，拆分合并需旧新映射并重新检查匹配，禁止静默改变批准素材的归属。
7. 参考中的营销表述不能自动当作已验证的商品事实。

阶段出口：审定模板、镜头需求和有来源的文案。候选切点未经复核不得标已审定。

### C. 统一投料后自动切分、分类和去重

1. 扫描 inbox 及已登记素材路径，只处理新增或变更文件。文件仍在复制时不入库，检查大小稳定且完整可解码。
2. 计算 SHA-256 识别相同文件，分配稳定 asset_id。相同内容换名不作为新素材，保留别名和来源记录。
3. 对原片检测镜头并抽首中尾及动作帧；长镜头可按完整动作标记多个有效区间，避免切断关键动作。
4. 每区间生成 clip_id，记录源文件、source_id、起止秒数、源帧率、真实可用时长和预览。
5. 两层分类：
   - 内容标签：产品/型号、宠物或人物身份、场景、动作、景别、角度、光线、构图、产品可见度。
   - 模板用途：可匹配的 template_id、镜头 ID、匹配理由与不符点。
6. 文件夹名只作线索，最终看画面。低置信度、未知产品、混合动作和无法辨认内容保留待审，不强行分类。
7. 检查黑屏、模糊、异常画面、水印/字幕遮挡、有效裁切空间及用户提供的使用限制，记录淘汰原因。
8. 用多帧视觉指纹辅助建立 duplicate_group_id，识别重编码、裁切和同源重复。哈希不同不代表内容不同，单帧相似不直接定重复。
9. 报告原片数、可用区间数、独立重复组数、待审数和分类分布，不把重复副本计为独立素材。

阶段出口：有来源、有效区间、画面标签、指纹和状态的素材索引与预览。

### D. 为每个模板镜头建立素材池

1. 先过滤产品错误、动作缺失、时长不可满足等硬条件，再按参考画面相似程度排序。
2. 候选展示参考与素材帧对照、有效区间、匹配理由、风险和连续性限制。相似分数是排序依据，不伪装成准确概率。
3. matches.json 区分 candidate、approved、rejected、missing_material、low_confidence。未批准不可进入生产。
4. 已批准范围形成长期 pools.json；本任务所需素材复制到 material/fragmentNN/。扩大区间、变更产品或镜头需求后重新审核。
5. 输出每镜头候选数、批准数、独立重复组数、有效时长和缺料类别。关键镜头争取 3 个以上独立候选是备料建议，不是产量承诺。
6. 缺料报告说明产品、动作、景别、角度和最低时长，不用无关素材填空。

阶段出口：每个必需镜头至少一个可用批准候选，否则不生产完整成片。

### E. 组合计划与批量差异控制

1. 先生成 batch-plan.json：唯一 variant_id、模板版本、选中区间、文案版本、随机种子、组合签名和策略参数。
2. 固定语义骨架，仅调整明确允许的镜头顺序；前后对比、因果和角色身份不能被随机打乱。
3. 单条内优先不重复同一重复组；三个连续镜头尽量避免同一来源文件夹，相邻避免明显重复房间、构图和语义场景。角色连续优先，例外记录原因。
4. 条与条优先替换开场、中段有效画面和收尾；同一原片的相近裁切不能直接算新场景。
5. 默认保持已确认文案。允许改写时只在授权范围变化表达，不添加无依据的性能、价格或效果承诺，改写后重新配音对齐。
6. 同时检查本批次与历史输出，不仅比较相邻两条。求解设尝试次数上限；组合不足报告实际数量，不硬凑。
7. 候选数相乘仅是理论组合数，不能当可交付数量。

内部起步规则（待样片校准，保存于批次参数，不是平台标准）：

| 指标 | 默认规则 | 处理 |
| --- | --- | --- |
| 完全重复组合 | 同样的重复组、区间和顺序 | 拒绝 |
| 对应镜头差异率 | 同模板任意两版至少 40% 的对应镜头使用不同重复组，数量向上取整 | 不足重选 |
| 共用画面时长占比 | 各重复组在两版累计时长取较小值后相加，除以较短成片时长，最多 60% | 超出重选或标未达标 |
| 开场 | 优先使用不同重复组 | 不足列为复核项，不宣称已去重 |

共用时长使用保守估计：同重复组不同裁切仍计共用，后续可增加区间匹配提高精度。不同模板不计算对应镜头差异率，仍查共用画面与多帧相似。视觉指纹阈值需样本校准，不凭空固定。例外不能静默放宽阈值或计入合格数量。

阶段出口：通过检查的组合计划、可生产数量、缺料及差异报告。未通过前不整批高分辨率渲染。

### F. 配音、时间线、单条样片

1. 默认使用豆包 TTS 生成新配音，不保留参考音轨。配置缺失则标待配音；替代服务遵循本次授权。
2. 按语义段生成并记录真实时长、文本、音色、参数和文件；相同输入可缓存复用。
3. 按实际语音时长分配画面，显式记录停顿；一个语义段的多个镜头按参考比例及素材约束分配。
4. 画面默认 1.00x。长素材选择完整动作区间；短素材先换候选，再考虑合理定格，记录补足时长。明显影响观看则补料，不变速硬拉。
5. 总时长超出容差时，按授权调整文案或 TTS 参数后重新生成实测；没有删改授权不擅自删词。
6. 字幕按语义断句、位于所属片段，一句跨镜头时拆为对应事件，不遮挡产品、关键动作和重要信息。
7. 检查配音开头、中间边界、最长停顿、最紧字幕边界和结尾。
8. 先做一条代表样片与草稿，验证声音、产品、裁切、字幕和节奏；沿用已有确认，否则样片规则审核后再整批。

阶段出口：真实音画时间线、样片、草稿与检查结果。

### G. 批量渲染和验收

1. 每版独立时间线、预览、成品、草稿，复用已通过的样式和缓存。
2. 默认 9:16、1080×1920、60fps。30fps 源转 60fps 不改变播放速度，不宣称获得原生 60fps 动作细节。
3. 命名 YYMMDD-platform-product-序号.mp4，英文缩写优先，避免覆盖；任务 ID 和 variant_id 唯一识别跨批次版本。
4. 检查解码、比例、分辨率、帧率、实际时长、音轨、音画覆盖、字幕越界、源区间越界、黑帧和异常长定格，区分预期停顿与异常静音。
5. 渲染后再次查本批次及历史相似，不能只凭组合计划判去重。没运行的检查标 not_run，不记通过。
6. 每版检查关键帧及开头/中段/结尾，问题版完整复看；重点复核样片、重复度最高版本和连续性例外。
7. 剪映草稿必须新建可编辑，不能覆盖原生或加密缓存。内容 ID、元数据 ID、根索引 ID 一致，各版唯一；素材路径存在，媒体源范围不超真实时长。
8. 草稿做结构校验，并验证代表草稿能打开、素材可见且可编辑；没有剪映环境则标打开验证待完成，不能仅有 JSON 就宣称验证可用。

阶段出口：合格与未达标数量、成片/草稿、差异及技术检查报告。

### H. 审核、归档和历史回写

1. 每版记录 review_pending、approved、rework 或 rejected，渲染成功不等于用户通过。
2. 渲染后即登记历史及状态，防止下一批重复生成待审核版本；失败方案只保留日志，不算合格。
3. 用户确认后才迁入 final。部分通过则只归档对应版本及依赖，共享素材复制，保留其他版本可用。
4. 归档前打包媒体或修复草稿路径；归档后重新检查引用和打开状态，失败不标归档完成。
5. 回写使用次数、最近使用任务和审核结果。没有实际数据不能宣称某镜头转化更好。

## 5. 机器可读契约

以下为待实现/扩展的要求，不能声称已有 schema_version: 1 文件全部支持。新增字段显式升级与迁移。

| 文件 | 核心字段 |
| --- | --- |
| assets.jsonl | asset_id、来源标识、路径及别名、SHA-256、媒体信息、产品分组及原片状态 |
| clips.jsonl | clip_id、asset_id、源区间、预览/参考帧、指纹版本、duplicate_group_id、标签、限制、审核状态 |
| template.json | template_id、版本、产品、参考哈希、审定镜头、语义映射、连续组、可变范围 |
| pools.json | 模板版本、镜头 ID、批准 clip_id/区间、匹配理由与审核记录 |
| recipe.json | 任务身份、模板版本、参考、数量、输出、时长容差、配音、镜头、策略和阶段状态 |
| matches.json | 镜头 ID、候选/批准区间、复制路径、证据、缺料与审核记录 |
| batch-plan.json | 目标/可行数量、阈值、历史快照、每版组合/种子/文案及检查结果 |
| timeline.json | 素材 ID、源区间、轨道目标时间、速度、定格、语音/字幕映射、总时长 |
| reports/ | 覆盖、差异逐对结果、媒体/草稿检查、待审项及错误 |
| outputs.jsonl | 任务/版本/模板、内容组/区间、组合/音频/成品指纹、时长、路径、审核及归档状态 |

## 6. 增量运行与恢复

- 素材哈希不变复用分析，模板版本不变复用审定镜头，TTS 输入不变复用音频。
- 阶段完成同时要求文件存在与检查通过，保存输入、状态、输出、错误和下一步。
- 重跑不得清空批准素材、审核和历史；结构改变先备份再迁移，下游过期只标需重建。
- 时间线缓存依赖模板、区间、文案/音频及输出参数，变更只重建受影响版本。
- 派生文件先写临时文件，验证后替换；索引串行或加锁提交，防止并发丢记录。
- 单版失败局部重试，不覆盖已审版本，不将失败数量计入完成数。

## 7. 验收与交付

- 必需镜头均有批准素材，缺料及低置信度明确暴露，不用无关素材硬凑。
- 产品、动作、场景、角度、光线、构图和可见度基本匹配，关联 AI/角色保持身份连续。
- 原片未破坏，来源和区间可追溯，改名副本不当独立内容。
- 批次与历史检查真实执行，差异规则达标或明确标未达标。
- 数量、比例、分辨率、帧率、实际时长满足本任务；偏差报告具体值。
- 画面默认 1.00x，配音按真实时长对齐并完成边界检查，字幕不越界遮挡。
- 草稿新建可编辑、ID 一致且唯一、路径有效、源范围合法，打开验证状态真实。
- ASR、TTS、声音克隆、查重、渲染和草稿验证只有实际运行并有文件才能声称完成。
- 用户确认后归档，归档后草稿及媒体仍可用。
