# 素材匹配、豆包配音与剪映草稿

先定位用户的项目根目录，读取其中 AGENTS.md、任务说明和最新报告，再读取 recipe.json、matches.json 与素材索引。从最后通过的阶段恢复，不重新索取已有确认。

## 使用范围与实现边界

本技能提供经过单产品试运行的工作方法和原型源代码，不是通用一键视频工厂。使用前阅读 [运行边界与入口](references/implementation.md)。历史脚本可能写文件、更新索引、覆盖旧结果，并依赖未随 Git 发布的媒体、旧草稿和机器环境；先审查输入输出，不直接逐个执行。

素材阶段阅读 [分类细则](references/material-classification.md)。完整流程约束见 [项目规范](references/workflow-rules.md)。项目用户的当前指令优先。

## 生产要点

1. 原始素材只读或复制，按哈希增量处理。参考不能自动进入生产池。先按产品、动作、场景、可用时长筛选，再按画面相似度排序；相似分数不是概率。
2. 区分候选、预览允许、正式批准和缺料。低于任务阈值不硬凑，区间扩大或换镜头先复核首中尾和动作帧。缺必需素材时只能生成明确标记的审核版。
3. 豆包音色、资源ID、语速来自本次任务；凭据通过用户指定的环境变量或本机密码输入获取，不写入日志。先验证短句，再按语义段生成；缓存必须包含音色、文本、语速及输出参数。不要将某次熊二音色、+50语速或31.7秒目标当作通用默认。
4. 实测每段音频时长后排时间线。一句话可跨多个相关镜头。首尾静音清理保留余量，不擅自删词或压缩内部停顿。总时长超容差，按授权调TTS语速并重新生成实测，不假定参数等于精确时长比例。
5. 画面默认原速；任务允许时才轻微变速（本次案例允许0.90～1.10）。自动定格、循环补时关闭；优先换长区间或补充相关镜头，无法覆盖则明确缺料。30fps转60fps不是增加原生动作细节。
6. 新建草稿：视频、语音、字幕独立轨道；媒体复制到项目中并使用真实绝对路径。内容、元数据、根索引的草稿ID一致，所有对象ID唯一。不能覆盖其他原生草稿或根索引；归档/迁移后修复路径。
7. 验证完整解码、音轨、实际时长、字幕范围、源区间和速度。JSON结构校验不等于剪映实际打开验证；未打开时明确待验证。保留烧录字幕、型号未确认和缺料等实质限制。
8. 向用户交付样片、字幕、草稿和报告；记录输出历史与审核状态。用户批准样片不自动代表所有缺料已解决或已批准归档。

## 代码与案例

[原型源码及还原说明](references/prototype-source/README.md)保留拆解、入库、匹配、TTS、渲染、草稿的实际脚本。媒体、模型、密钥和机器环境不随仓库发布。修改原型时优先参数化路径和配置，并确保不覆盖旧审批或已确认输出。

[发布审计](references/release-audit.json)记录本次本地文件完整性和未完成事项。它是时间点记录，不代表安装者的环境已验证。
